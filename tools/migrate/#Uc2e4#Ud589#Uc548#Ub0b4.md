# 운영 데이터 옮기기 — 실행 안내 (관리자용, 프로그램 설치 불필요)

BDTS-main(구글 시트)의 자료를 포털(Azure)로 옮길 때마다 아래 순서대로 합니다. 10분 안에 끝납니다.

## 준비물
- 구글 시트에서 내려받은 **거래처이력카드.xlsx** 한 개 (시트 전체: records · claim_progress · claim_extra · csc_reference_log · cartridge_log 탭 포함)
- 포털 **관리자 계정**

## 순서
1. 포털에 관리자로 로그인 → 홈 맨 아래 **[운영 데이터 옮기기]** (왼쪽 레일 Control 그룹에도 있음)
2. **1단계 [건수 세어보기]** — 지금 Azure 에 든 건수가 표에 나옵니다.
   - "지우기" 체크는 기본값 그대로 두면 됩니다. (병원 참고사항 · 대리점 정식 명칭 · 엑셀 업로드분 Blob 은 기본으로 **남김**)
3. **2단계** 상자에 **거래처이력카드.xlsx 를 끌어다 놓기** (또는 눌러서 고르기)
   - 화면 안에서 바로 변환되어 "넣을 곳별 건수"와 "검토 사항"이 나옵니다. 이 단계까지는 Azure 에 아무것도 쓰지 않습니다.
   - **[📄 검토 리포트 내려받기]** 를 눌러 보관하세요. "읽지 못해 비워 둔 날짜"가 있으면 이관 뒤 화면에서 직접 고치면 됩니다.
   - 날짜 확정값이 더 생기면 `overrides.json` 을 xlsx 와 **함께** 넣으면 적용됩니다. (형식은 tools/migrate/overrides.json 참고. 지금까지 확정한 3건은 화면에 이미 들어 있습니다)
4. **3단계** 확인 체크 → **[지우고 넣기]** → 확인 팝업 [확인]
   - 진행 막대가 100% 가 되고 "제대로 들어갔는지 다시 세어봅니다" 가 끝나면 4단계 결과 표에 **일치** 가 떠야 합니다.
5. 거래처 이력카드 · 고객지원센터 · 클레임 로그 (국내) 화면을 새로고침(Ctrl+Shift+R)해서 확인합니다.

## 주의
- 이 작업은 되돌릴 수 없습니다(휴지통에 남지 않음). 체크한 저장소의 **포털에서 직접 입력한 자료도 함께 사라집니다.**
- 정식 전환(BDTS-main 사용 중단) 직전에 **마지막 xlsx 로 한 번만 더** 실행하고, 그 뒤로는 실행하지 않습니다.
- 한 번에 한 사람만 실행하세요. 실행 중에는 브라우저 탭을 닫지 마세요.

## 참고
- `tools/migrate/convert.py` 는 같은 규칙의 터미널 버전(개발·검증용)입니다. 화면에서 xlsx 를 넣는 것과 결과가 같으므로 따로 실행할 필요는 없습니다.
