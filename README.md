## ★ 알아두셔야 할 것 — 관리번호가 겹칩니다

기존 자료에 **같은 관리번호를 쓰는 서로 다른 클레임이 124건** 있었습니다.

```
2509-CC-040K  2025-09-10  CK-MB      CK,MB 전혈 INVALID34 ...
2509-CC-040K  2025-09-01  (품목없음)  PCT 외부정도관리 사전조치
```

관리번호만으로 중복을 판정하면 이 124건이 사라집니다.
그래서 판정 기준을 **관리번호 + 접수일 + 제목**으로 바꿨습니다.
셋이 다 같을 때만 건너뜁니다. 관리번호 부여 규칙 자체를 정리하시는 편이 좋겠습니다.

## 파일 구성 — 자료는 한 곳에만 둡니다

같은 자료를 두 벌 두면 한쪽만 갱신됐을 때 화면끼리 숫자가 어긋납니다.
그래서 자료마다 원본을 하나만 두고, 여러 화면이 같은 파일을 읽습니다.

| 자료 | 원본 파일 | 읽는 화면 |
|---|---|---|
| 통합 클레임 로그 | `data/claims-YYYY.json` | 통합 클레임 로그, 통합 검색 |
| 클레임 로그 (국내) 씨앗 | `data/domestic-rows.js` | 클레임 로그 (국내), 통합 검색 |
| 거래처 이력 | Azure `client_cards` (거래처 이력 화면에서 저장) | 거래처 이력 · 클레임 로그 (국내) 연동 |
| Sales | `sales-data.js` | Sales Report, 통합 검색 |
| 업무 가이드 · 장비 | `guide-data.js`, `device-data.js`, `info-docs.js` | 정보, 통합 검색 |

`data/domestic-base.js` · `domestic-extra.js` · `domestic-rows.js` 는 자동 생성 파일입니다.
(만들어낸 원본 `domestic-seed.json` · `domestic-extra.json` 은 저장소에서 이미 빠져 있습니다.)

## 2026-09 피드백 반영 (2차)

- **거래처 이력 세트화**: 고객지원센터와 같은 구조 — 카드 `sets[]`(기기 + 시약 여러 개 + 접수/조치사항 + 분류 + 사진) + `logMap[]`, **세트의 시약 1개당 마스터로그 1건**. 예전 카드는 `clSetsOf`가 세트로 읽고, `devices[]`는 로그 1건당 1행으로 `clSyncDerived`가 다시 만듭니다
- **필수 칸**: 작성 전 노란 배경(거래처 이력 포함 — `#p-client` 규칙보다 우선하도록 선택자 보강), 저장 시 빠진 칸은 굵은 빨간 테두리 + 빨간 배경 + 라벨 빨강 "← 필수". "마스터로그 미반영"은 빨간 배지
- **고객지원센터**: 신규 접수 화면이 다른 탭에서도 보이던 문제(`#sv-entry` 가 항상 flex) 수정. 진행상황 검색 아래 **클레임 로그 (국내) 요약**(건수 · On Going · 월별 · 아이템/장비/분류/병원 순위 · 최근 8건 내용·회신) + 통합 검색 종합 요약 링크
- **수정자·시각**: 저장 직후 화면의 마지막 수정자·시각을 바로 갱신(`stampEdit`), 모든 시각은 브라우저 로컬(한국) 시간으로 표시(`fmtLocal`, 변경 이력 페이지 포함)
- **이동 경고**: 수정 팝업이 열려 있을 때도 탭/메뉴 이동 시 확인, 브라우저 탭 닫기·새로고침 시 `beforeunload` 경고
- **화면 폭**: 통합 클레임 로그·통합 검색은 화면에 꽉 차게, 나머지는 가운데 정렬
- **통합 검색**: 병원 참고사항(`hospital_notes`)이 검색어·병원 조건에 걸리면 결과 위에 표시
- **고객지원센터 › 신규 접수 옆 패널 [이력 요약]**: 병원·대리점·아이템·LOT·담당자를 넣으면(병원명을 고르면 자동) 클레임 로그 (국내)만 기준으로 규칙 기반 요약문(기간·건수·진행·아이템/장비/분류/병원 순위·최근 추이·최근 건)을 보여줍니다. 진행상황 검색은 고객지원센터 접수만 찾습니다. 대리점명은 AFIAS 사용자 리스트의 "대리점 → 병원" 관계로 담당 병원 로그를 모읍니다. 과거 마스터로그는 이 화면에서 처음 쓸 때 읽어옵니다(`ensureRows`)
- **통합 검색은 클레임 로그 기준**: 거래처 이력카드·고객지원센터 접수는 검색 대상에서 제외(두 화면의 저장 내용은 클레임 로그 (국내)로 함께 만들어지므로 중복 방지). 대상 = 통합 클레임 로그(연도별) + 클레임 로그 (국내) + 가이드. 종합 요약도 클레임 로그만 집계

  `ui-common.js` 에서 그래프 크기·마우스 위치를 zoom 과 무관하게 계산하고(모든 그래프 화면 공통), `assets/theme.css` 에서 그래프 칸이 안의 폭에 끌려가지 않게 했습니다.
  같은 원인으로 가장 큰 막대 외에는 눌러도 목록이 안 열리던 문제도 함께 해결.
- **포털 메인 "최근 30일 클레임 TOP"** (`assets/home-top.js`): 오늘 포함 30일, 해외(청회색)·국내(올리브) 나눠 아이템 / LOT No. / 대리점(국내는 거래처) 상위 5.
  - 해외 = 통합 클레임 로그. 국내 = 기존 건은 통합 클레임 로그, 통합 클레임 로그에 없는 번호(새로 작성한 건)는 클레임 로그 (국내). 같은 번호는 한 번만.
  - 칸은 늘 5줄(5가지가 안 되면 "—"), 아이템·LOT 칸은 대리점 칸의 반씩, 해외·국내 패널 크기 동일. 칸 제목 옆에 "N가지뿐 · 미기재 N건 제외" 표시.
  - 대리점 이름이 길면 `Labindustrias…; Guatemala` 처럼 회사명만 줄이고 국가는 남김. 항목을 누르면 해당 클레임만 팝업으로(최신순, 줄을 누르면 Complaint·Investigation·Reply·사진).
- **기록하기 뒤로가기**: 포털 메인 → 거래처 이력 / 고객지원센터 / 클레임 로그 (국내) → [뒤로] 가 "기록하기" 중간 화면으로 가던 문제.
  화면 준비 중·초기화 중에 뒤로가기 기록이 몰래 쌓이던 것을 막아(`pages/records.html` 의 `nav()`), 바로 포털 메인으로 나갑니다.
  다른 화면에서 클레임 로그 (국내)로 온 뒤 [뒤로] 가 "직접 입력" 탭으로 가던 문제도 함께 해결.

## 2026-09 운영 로그 추가 (2026-09-10)

**변경 이력**이 "누가 · 무엇을 바꿨나"라면, **운영 로그**는 "무엇이 잘못됐나"를 남깁니다.
관리자 화면 `pages/audit.html` 의 **[운영 로그]** 탭에서 보고, 포털 메인 관리자 칸에 **최근 7일 건수**가 뜹니다.

| 종류 | 언제 남나 | 남기는 곳 |
|---|---|---|
| 저장 실패 · 삭제 실패 · 불러오기 실패 | 저장소(`azure-store.js`)를 거치는 모든 저장·삭제·목록 읽기가 실패했을 때 | 화면 |
| 업로드 실패 | 엑셀을 못 읽었을 때(통합 클레임 로그 · Sales Report) · 업로드 저장 실패 | 화면 |
| 화면 오류 | 우리 코드에서 난 오류 (확장 프로그램·외부 스크립트 오류는 제외) | 화면 (`ui-common.js`) |
| 서버 오류 | API 가 500 을 돌려줄 때 (records · blobs · 로그인 · 비밀번호 변경 · 변경 이력 조회) | 서버 |
| 로그인 실패 · 잠김 | 비밀번호 불일치 · 명단에 없는 메일 / 10회 실패로 잠긴 순간 한 번 | 서버 |

- **남기지 않는 것**: 클레임 본문 · 병원 연락처 같은 내용. 메뉴 · 건번호 · 동작 · 오류 메시지만 남깁니다.
- **누가**는 화면이 적어 보낸 값이 아니라 서버가 로그인 쿠키로 정합니다. 화면은 서버 오류 · 로그인 기록을 꾸며 보낼 수 없습니다.
- 같은 문제는 화면에서 묶어 "N회"로 보냅니다 (한 화면 최대 50줄). 서버도 인스턴스당 1분 300줄을 넘으면 버립니다.
- **90일**이 지난 줄은 관리자가 운영 로그를 열 때 자동으로 지웁니다 (12시간에 한 번).
- 저장 위치: 같은 Table 의 `ops_log` 파티션. 새 Azure 설정은 필요 없습니다.
- ⚠ Azure 저장소 자체가 멈추면 운영 로그도 남지 못합니다. 그런 장애까지 보려면 Azure Application Insights 연결을 따로 검토하세요.

**보안 보강 (같은 날)**: `api/records` 로 로그인 · 비밀번호 · 변경 이력 · 운영 로그 저장소(`audit_log` · `user_secret` · `login_attempt` · `session_revoke` · `ops_log` 등)를
읽거나 쓰는 것을 모두 막았습니다. 예전에는 이관용 일괄 작업만 막혀 있어, 로그인한 사람이면 이 경로로 변경 이력 줄을 지우거나
남의 비밀번호 기록을 덮어써 초기 비밀번호로 되돌릴 수 있었습니다. 화면에서는 쓰지 않는 경로라 동작 변화는 없습니다.

**변경 이력 기간 검색**: 시작일·종료일을 한국 시간 자정 기준으로 바꿨습니다 (예전엔 UTC 자정이라 오전 0~9시 기록이 하루 어긋났습니다).

### 출장 보드 — 동행인 · 이름 직접 입력 (2026-09-16)

- 일정 추가·수정 창에 **동행인** 칸을 넣었습니다. 이름을 쓰고 Enter(또는 Tab·[추가])로 넣고, ×로 뺍니다.
  - 저장하면 동행인마다 **같은 내용의 일정이 따로 한 건씩** 생겨 각자 달력에 보입니다. 같은 동행 일정은 `groupId` 가 같습니다(`trip_trips`에 필드 추가, 예전 일정은 빈 값).
  - 여러 줄을 한 번에 넣으면 줄마다 동행 묶음이 따로 생깁니다. 휴가·부재에는 동행인 칸이 없습니다.
  - 동행인이 이미 같은 날·같은 병원 일정을 따로 적어 두었으면 새로 만들지 않고 그 일정을 묶습니다.
  - 묶인 일정 중 하나를 고쳐 저장하면 **동행인 일정도 같은 내용으로 바뀝니다**. 동행인을 ×로 빼고 저장하면 그 사람 일정이 지워집니다(휴지통). [삭제]는 연 사람의 일정만 지웁니다.
  - 달력 막대·칸에 마우스를 올리면 "동행 ○○○"가 보입니다.
- **팀원 이름 직접 입력**: 일정 창의 팀원 칸과 전체 달력의 팀원 필터가 드롭다운 대신 글자 입력(추천 목록 포함)입니다.
  - 이름 일부만 써도 한 사람에게만 맞으면 Tab·Enter 때 그 이름으로 채워집니다. 목록에 없는 이름은 빨간색으로 표시되고 저장되지 않습니다.
  - 전체 달력 필터는 비우면 전체입니다.
